El Problema

Las PyMEs no pueden acceder a sus propios datos

A pesar de ser el motor de las economías latinoamericanas, enfrentan barreras críticas para adoptar herramientas de Business Intelligence.

💰

Costos Elevados

Plataformas de BI que exceden el presupuesto en licencias e infraestructura.

👤

Sin Personal Técnico

Sin departamentos de TI ni analistas que dominen SQL o ciencia de datos.

🔗

Complejidad

Sistemas heredados incompatibles que generan resistencia al cambio.

Consecuencia

Los datos quedan subutilizados

Las decisiones se toman sin respaldo analítico, limitando el crecimiento empresarial.

Existe una necesidad urgente de soluciones de lenguaje natural que permitan democratizar el acceso a la información estructurada.

La Solución

Lenguaje natural como interfaz de datos

BIGENIA elimina intermediarios técnicos. El usuario pregunta en lenguaje cotidiano y obtiene gráficos interactivos.

💬

Entrada Natural

"Mostrar ventas por país" — sin escribir SQL.

🤖

Agentes de IA

Arquitectura multiagente que orquesta todo el flujo.

📊

Gráficos Interactivos

Plotly.js con zoom, filtrado y exploración.

Gemini Vanna AI PostgreSQL Plotly React LangSmith pgvector RAG

Arquitectura

Flujo de trabajo en 8 pasos

1Recepción de la consulta del usuario
2Caché semántico (base vectorial)
3Delegación al Agente Decisor
4Extracción de contexto (RAG)
5Generación Text2SQL
6Decisión de visualización
7Consolidación de resultados
8Renderizado del gráfico interactivo

Arquitectura desacoplada: cada agente asume un rol especializado, facilitando el mantenimiento y futuras actualizaciones.

Agente Decisor

🧠 Orquestador central

Clasifica la intención mediante Gemini con salida estructurada y enruta la consulta.

✅ Válida y clara

Continúa con el pipeline: SQL → Visualización.

❓ Válida pero ambigua

Genera pregunta de clarificación (máx. 1 consecutiva).

🚫 Fuera de alcance

Responde que excede las capacidades del sistema.

💬 Conversacional

Saludos, despedidas — respuesta apropiada.

También resuelve contexto: "lo mismo pero por mes" → consulta auto-contenida.

Agente Text2SQL

🗃️ Lenguaje natural → SQL

RAG para contexto

Embedding de la consulta → búsqueda por coseno en la documentación del esquema → inyección en el prompt.

Validación de seguridad

Solo SELECT. Escaneo de palabras destructivas (DELETE, DROP, UPDATE...). Bloqueo inmediato si se detecta.

Mecanismo de reintento

Si la SQL falla al ejecutarse:

  1. Captura el error de PostgreSQL
  2. Construye prompt de refinamiento
  3. Segunda invocación al LLM
  4. Re-validación y ejecución

Máximo 2 intentos, transparente para el usuario.

Agente de Visualización

📈 Datos → Gráfico interactivo

Pipeline de 5 etapas

  1. Validación de datos
  2. Análisis de metadata del DataFrame
  3. Decisión y generación de código Plotly
  4. Ejecución con loop de corrección
  5. Serialización a JSON

9 tipos de gráfico

Barras, líneas, torta, dispersión, histograma, mapa de calor, diagrama de caja, indicador, tabla.

Edición generativa

El usuario puede modificar gráficos existentes con lenguaje natural: colores, filtros, tipo.

Conclusiones

Viabilidad demostrada

  • Democratización efectiva de la analítica de datos en PyMEs mediante IA Generativa.

  • Abstracción total de la complejidad técnica — interfaz directa usuario ↔ base de datos.

  • Guardrails resilientes que mitigan peticiones fuera de dominio y garantizan integridad.

  • Límites claros en JOINs complejos, sin invalidar la utilidad estratégica.

  • Autonomía analítica real para organizaciones con recursos de TI limitados.
