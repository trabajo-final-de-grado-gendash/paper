La Solución

BIGENIA: lenguaje natural como interfaz de datos

Un sistema de Generative Business Intelligence (GenBI) que interpreta consultas en lenguaje cotidiano, las traduce en código estructurado y despliega los resultados mediante gráficos interactivos.

💬

Entrada en lenguaje natural

"Mostrá las ventas por país" — sin escribir una línea de SQL.

🤖

Arquitectura multiagente

Orquestación especializada que gestiona todo el flujo de principio a fin.

📊

Gráficos interactivos

Plotly.js con zoom, filtrado y exploración de datos en tiempo real.

Arquitectura

Flujo de trabajo en 8 pasos

1Usuario pregunta → Frontend envía al backend vía HTTP
5Generación de SQL por Agente Text2SQL + validación
2Caché semántico verifica respuestas anteriores idénticas
6Decisión de visualización por Agente Viz
3Delegación al Agente Decisor (orquestador central)
7Consolidación de resultados y preparación de respuesta
4Extracción de contexto via RAG (schema_documentation)
8Frontend renderiza el gráfico interactivo al usuario

Arquitectura desacoplada: cada agente asume un rol especializado. El LLM puede reemplazarse sin comprometer el flujo. Observabilidad integrada con LangSmith.

Agente Decisor

Orquestador central del pipeline

Clasifica la intención mediante Gemini con structured output. Esquema predefinido garantizado: cero parseo manual, cero ambigüedad.

Consulta válida y clara

Continúa el pipeline completo: generación SQL → ejecución → visualización.

Consulta ambigua

Genera una pregunta de clarificación. Máx. 1 consecutiva; luego asume la interpretación más probable.

Fuera de alcance

Guardrail: informa que la solicitud excede las capacidades del sistema.

Conversacional

Saludos y cortesías: respuesta apropiada sin activar el pipeline de datos.

Resolución contextual: "lo mismo pero por mes" → genera una consulta auto-contenida con el historial incorporado, sin exponerlo a las etapas siguientes.

Agente Text2SQL

Lenguaje natural → SQL ejecutable

Inyección de contexto (RAG)

Embedding de la consulta → búsqueda por distancia de coseno en schema_documentation → inyección de DDLs y reglas de negocio en el prompt. Reduce significativamente las alucinaciones.

Validación de seguridad

Solo SELECT. Bloqueo inmediato si detecta DELETE, DROP, UPDATE, INSERT, ALTER. Temperatura del modelo: 0.

Mecanismo de autocorrección

Si la SQL falla al ejecutarse:

  1. Captura el error exacto de PostgreSQL
  2. Construye un prompt de refinamiento con el contexto del error
  3. Segunda invocación al LLM con temperatura 0
  4. Re-validación de seguridad y ejecución

Máximo 2 intentos · transparente para el usuario

Agente de Visualización

Datos → Gráfico interactivo

Pipeline de 5 etapas

  1. Validación de datos recibidos
  2. Análisis de metadata del DataFrame
  3. Decisión del tipo de gráfico + código Plotly
  4. Ejecución en sandbox con loop de corrección
  5. Serialización a JSON para Plotly.js

Edición generativa

"Hacé el gráfico verde" · "Filtrá por 2024" · "Pasalo a líneas" → modificación inmediata preservando el código y contexto base.

9 tipos de gráfico soportados

El modelo justifica su elección con un razonamiento explícito presentado al usuario. Salida: JSON Plotly.js, código fuente, tipo de gráfico y métricas de ejecución.

Evaluación

LLM-as-a-Judge

Evaluar SQL + gráficos mediante comparación exacta de texto es insuficiente. Se emplea un modelo avanzado como juez imparcial, provisto de una rúbrica estricta, para auditar el ciclo analítico completo.

🎯

IntentJudge

¿Clasificó correctamente la intención del usuario según el contexto de la sesión?

🗃️

SQLJudge

¿El SQL resuelve la pregunta? ¿Tablas, filtros y JOINs son correctos en el esquema?

📊

PlotlyJudge

Ejecuta el código Python/Plotly en un sandbox seguro y verifica que la figura compile.

35 casos de prueba · 4 categorías (válidas, conversacionales, fuera de dominio, ambigüedades) · Modelo juez: gpt-oss-120b vía Groq · Puntaje continuo 1–5 + justificación · Integrado con LangSmith

Structured output de Gemini hace la clasificación infalible. Guardrails detectaron el 100% de peticiones fuera de dominio.

Penalizaciones menores en aspectos estéticos del gráfico, no en fallos de ejecución bajo sandbox.

Degradación leve en JOINs múltiples. El mecanismo de reintento mitiga la mayoría de errores sintácticos.

Conclusiones

Viabilidad demostrada empíricamente

✅

Democratización efectiva — la analítica en PyMEs es alcanzable con IA Generativa sin intermediarios técnicos ni conocimientos de SQL.

🔒

Guardrails resilientes — el sistema identifica y mitiga consistentemente peticiones fuera de dominio y consultas destructivas (100%).

🔄

Autocorrección efectiva — el mecanismo de reintento eleva la tasa de éxito final, reduciendo errores de forma transparente para el usuario.

⚠️

Límite operativo identificado — degradación en JOINs complejos, sin invalidar la utilidad estratégica del sistema en el dominio PyME.

🚀

Base para herramientas de próxima generación — arquitectura extensible a múltiples fuentes de datos, modelos y dominios empresariales.
